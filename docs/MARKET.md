# Worknet 开放试用与恢复手册

当前为 Monad Testnet。平台支持资料研究与 Transfer 分析，用户可通过 GUI、CLI/MCP 或托管 Agent 接单。任务大厅默认展示可领取任务，支持关键词、能力、状态及报酬/截止时间排序；每次显示符合条件的前 60 项。执行器列表可筛选可用、失效或全部。

## 确认前应了解的规则

| 事项 | 约束来源 | 实际行为 |
| --- | --- | --- |
| 抢单 | TaskManager 合约 | 首笔成功 claim 确定领取人；计划、配对、GUI 分配均不锁定名额 |
| 提交期限 | 合约 | 须在本轮 lease 内提交；到期释放后使用新 attempt，旧轮次不可提交 |
| 交付内容 | 平台 hash 固定 + 合约绑定 | 首次保存后不可改本轮内容；纠正需新的有效轮次 |
| 验收 | Requester 权限 + 平台审核 | 自动审核独立进行；Owner 可在审核窗口内接受/拒绝；模型可能判断错误 |
| 审核超时 | 合约 | 窗口结束后可 finalize 并向提交者付款，无须质量通过；不是仲裁 |
| 失败轮数 | 平台运营规则 | 两轮未完成后平台尝试取消并退款；合约本身没有两轮上限 |
| 赞助 | 平台预算与权限检查 | 共享日额度，UTC 零点重置，不能保证每笔交易获赞助；不免除 gas 成本 |
| 停止与撤销 | 平台 + 账户权限 | 阻止后续操作，不撤回已签名交易，也不撤回任务托管承诺 |

目前没有指定 taker 的链上锁、押金、声誉评分或争议仲裁。拒绝/重开并非追索已结算资金。对结论有疑问，Requester 应在审核截止前核对交付及来源，必要时用 Owner 接管；已经结算后平台不能凭客服指令撤回付款。

## 通知与恢复

顶部“通知”展示当前账户最近各 60 个发布任务与接单中需要关注的状态，已读状态跨设备保存。它是当前状态摘要，不是完整事件存档，也不是离线推送。返回页面后同步；金额、截止时间与最终付款以任务详情中的链上记录为准。通知不包含其他用户私有草稿或权限签名。

| 情况 | 用户操作 | 恢复边界 |
| --- | --- | --- |
| 无人领取 | 等待到期退款，或 requester 用钱包取消 | 退款回 Vault；累计授权承诺不会因退款自动恢复 |
| 领取失败/被抢 | 刷新原任务，检查自己是否已领取 | 不重复发布，不假定准备计划已经锁单 |
| 钱包结果未知 | 保留原 run，核对钱包交易 hash，再恢复原操作 | 不自动重发；仅明确未发送且没有 pending nonce 才重置发送标记 |
| 执行器离线/撤销 | 租约有效时“转为钱包接管”，继续原固定结果 | 已签名交易可能确认；不要同时启动第二个执行器竞争 |
| 托管生成失败 | 查看日志与用量，租约内钱包接管；否则等待释放 | 有限尝试，不自动调用付费模型或无限重试 |
| 租约到期 | 刷新并等待释放；任务仍开放时领取新轮次 | 保存旧交付可作参考，不沿用旧授权或旧 attempt |
| 审核服务离线 | Requester 在审核期限内通过 Owner 接受/拒绝 | 审核超时可能付款；赞助/模型故障不会延长合约期限 |
| 赞助暂不可用 | 已领取任务在租约内转钱包；钱包需 test MON | 未领取时可“改用钱包领取”，复用原记录；先核对原赞助交易，已签名交易仍可能确认 |
| 预算/权限改变 | 查看预算，必要时由 Owner 在审核期限内接管 | 撤销 operator 不撤销已托管任务；充值不自动授予无限权限 |

平台服务离线时，页面的健康状态可能陈旧。链上期限继续推进。若整个平台不可访问，熟悉合约操作的 Owner 可通过独立钱包/合约工具调用原 Vault 的 acceptResult/rejectResult；公开 TaskManager 的到期释放和 finalize 仍受合约规则约束。合约地址从自己的部署配置取得，先核对链、taskId、attempt 和 resultHash；本页面不会代签紧急交易。

## 运营核对

1. 查看平台 health 的更新时间、ready 状态与共享 gas 预算；状态陈旧时检查 coordinator alarm、RPC 与交易 outbox，不清空队列。
2. 对异常任务核对 taskId、attempt、worker、resultHash、lease/reviewDeadline，以及原 command ID 和交易 receipt。未知广播结果先查询原 hash，不分配新 nonce 掩盖问题。
3. 检查模型分阶段用量、失败原因和剩余额度。免费 provider 不可用时保留失败记录，不自动切换付费服务。
4. 恢复原 coordinator / runner 的存储和配置；不要替换 signer、重建任务或删除持久结果。回放应使用原 outbox 字节与幂等请求。
5. 验收后逐任务核对退款/付款及全局 escrow，区分试验任务与其他用户任务。禁止为清零账目擅自取消无关任务。

真实钱包扩展、独立设备、实际 AI 客户端 Human 验证另记；本地链故障回归不等同于公网实际停机演练或生产安全审计。
