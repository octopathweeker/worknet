M6：judge quorum 结算已接入云端平台，并在独立 Testnet 环境部署。TaskManager `settleWithVerdicts` 以 M-of-N EIP-712 签名链上取完成度中位数分账；三个独立 judge Worker 核对链上绑定、来源证据并通过 OpenRouter Jev 评分，复用原平台 Secret。平台持久收签、幂等结算，GUI 展示实际付款与退款（完整 USDC 精度）。新 Manager/Factory、D1、角色密钥和站点与旧版本隔离，旧预算需由 Owner 自行提现后重新充值授权。真实公网已验证平台执行与外部钱包开放接单两条路径的比例付款及退款；28 Foundry、88 Node 回归通过。联盟式信任：judge 集合固定、共享同类模型、无 staking；仍保留 Owner accept/reject 与审核超时全额付款规则。真实钱包扩展和独立设备 Human 验证尚未完成。见 [M6 上线说明](M6-RELEASE.md)。

研究测试曾出现“引文真实但不足以支持结论”的自动审核假阳性，随后增加逐项引文支持审核、范围约束与有限修订。失败任务可拒绝、重开和退款；不宣称任意模型任务必然正确。此快照不携带原始账户、付款明细或维护者环境的验证日志。

用 `pnpm check` 在自己的环境重现构建、类型检查、合约与 Node 回归。合约资金与权限、账户 replay/revoke/expiry、双用户隔离、崩溃恢复、金额编码、充值路由与收据核验均有测试。R4 另覆盖外部接单崩溃恢复、跨任务/attempt 越权拒绝、双执行器隔离、撤销后钱包接管，以及旧轮次不会继承后续验收/付款。
